Em geral, todos os parâmetros têm um código, uma etiqueta e uma descrição

*	A etiqueta é apresentada em todas as vistas do MONARC.
*	A descrição é a etiqueta que normalmente aparece na dica de contexto.

=== Tipo de ativos

Existem dois tipos de ativos:

*	Ativos primários ou de negócio: Geralmente representam, mas não se limitam a, serviços, processos ou informação internos ou externos. São os que estão na raiz da análise e que irão diminuir o seu impacto sobre outros ativos. Os contentores usados para organizar visualmente a análise são declarados como ativo primário (por exemplo, __Back Office__).
*	Ativos secundários ou de suporte: São os ativos aos quais os riscos estão associados; são usados para descrever o perfil de risco dos ativos primários.

=== Ameaças

Os parâmetros essenciais das ameaças estão alinhados com os critérios CID. É importante, ao criar uma nova ameaça, especificar corretamente estes critérios, porque influenciarão as tabelas de risco.
Exemplo: A escuta passiva (ouvir, observar sem tocar em nada) é uma ameaça que, por exemplo, afeta apenas o critério de confidencialidade.
As ameaças têm temas para gerar estatísticas.

===	Vulnerabilidades

As vulnerabilidades devem descrever negativamente o contexto de risco. Quanto maior a vulnerabilidade, menos existentes ou eficazes são as medidas. A vulnerabilidade é inversa à maturidade.
Exemplo: «Ausência de identificação de bens sensíveis»: Baixa vulnerabilidade se os bens sensíveis estiverem identificados e, inversamente, a vulnerabilidade é grande se não estiverem.
A descrição da vulnerabilidade é muito importante porque aparece na tabela de risco como uma descrição adicional que ajuda o especialista de segurança a refinar um questionário ou os pontos precisos que se procuram acerca de um risco.

=== Riscos de informação

Esta tabela é o núcleo da base de conhecimento do MONARC. É aqui que se fazem as associações entre _Tipo de ativo_, _Ameaça_ e _Vulnerabilidade_.
A combinação de riscos inerentes a cada ativo será proposta por predefinição quando o modelo de risco é criado.
Para cada associação, que pode ser considerada um cenário de risco, é possível associar medidas de segurança a partir dos separadores de referenciais.
Apenas os ativos de suporte estão disponíveis para associações Ameaça/Vulnerabilidade.

=== Etiquetas (Riscos operacionais)

A disposição da tabela de etiquetas é muito semelhante às anteriores.
Tal como nas tabelas descritas acima, pode adicionar um elemento (etiquetas), pesquisar entre elementos, repor os filtros ou exportar os itens como ficheiro CSV.

As etiquetas representam uma categorização dos riscos operacionais. É um agrupamento lógico de riscos que podem depois ser associados a ativos primários.

[#fig-tagstable-1-800]
.Tabela de etiquetas
image::TagsTable_1_800.png[Update controls,pdfwidth=90%,width=90%,align=center]

=== Riscos operacionais

É uma lista de riscos criados por predefinição ou adicionados especificamente. Cada risco pode ser associado a uma ou mais etiquetas, o que permite, ao depositar um ativo na análise, propor riscos predefinidos, tal como acontece com os riscos de informação.
É possível associar controlos de segurança aos riscos de informação.

[#fig-operationalriskstable-1-800]
.Tabela de riscos operacionais
image::OperationalRisksTable_1_800.png[Riscos operacionais,pdfwidth=90%,width=90%,align=center]

1.	Adicionar um risco operacional
2.	Pesquisar entre os riscos operacionais
3.	Filtrar entre etiquetas
4.	Escolher entre normas (ISO 27002, NIST Core, etc.)
5.	Repor filtros
6.	Controlos de atualização
7.	Exportar para um ficheiro CSV
